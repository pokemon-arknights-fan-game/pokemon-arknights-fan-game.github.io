# 보유 카드와 덱

## 이용 흐름

로비 → 카드 팝업 → 덱 편성 → 덱 목록 → 새 덱 또는 기존 덱 수정 순서입니다. 보유 카드 화면은 151종을 보여주며 검색·등급 필터를 제공합니다. 편집 화면 왼쪽은 보유 카드, 오른쪽은 편성 목록입니다. 추가/빼기로 수량을 바꾸고 이름을 입력해 저장합니다. 저장하지 않고 나가면 편집 중인 변경은 버립니다.

- 모든 종류를 3장씩, 총 453장 보유하는 임시 설정입니다.
- 덱은 0~40장으로 저장할 수 있습니다. 빈 초안도 이름을 붙여 보관할 수 있습니다. 전투 선택은 정확히 40장일 때만 가능합니다.
- 한 종류는 보유량과 3장 중 작은 값까지 편성합니다.
- 여러 덱에서 같은 보유 카드를 사용할 수 있습니다. 덱 저장은 소유 카드를 소비하거나 예약하지 않습니다.
- 처음에는 기존 훈련 포켓몬을 우선 넣고 다른 종류로 채운 40장 기본 덱을 제공합니다. 종류별 3장 제한을 지킵니다.
- 덱 목록에서 수정·삭제가 가능합니다. 삭제 버튼은 한 번 더 확인해야 삭제됩니다.

로비의 전투 메뉴는 덱 선택 화면을 엽니다. 선택한 덱의 사본을 전투에 전달합니다. 전투 중에는 저장된 덱 목록이나 보유량을 변경하지 않습니다. 선택한 덱이 없으면 전투 선택 화면으로 안내합니다.

## 저장

덱과 선택한 덱 ID는 현재 브라우저·출처의 localStorage에 저장합니다. 새로고침 후에도 유지됩니다. 다른 브라우저나 다른 주소·포트, GitHub Pages와 로컬 서버는 저장 공간이 다릅니다. 서버나 계정에 업로드하는 저장은 아닙니다.

저장소가 차단되거나 용량이 부족하면 이번 실행의 메모리에만 유지하고 화면에서 안내합니다. 불러온 데이터의 형식·카드 ID·수량·중복 덱 ID를 다시 확인합니다. 지원하지 않는 저장 형식·손상 JSON은 기본 데이터로 시작합니다. 지원되는 형식 중 잘못된 개별 덱은 제외합니다.

## 전투 카드 수명

선택한 덱의 각 실물 카드에 고유 instanceId를 부여하고 무작위로 섞습니다. 손패는 고정 9장을 기본 규칙으로 뽑고 사용 후에도 9장까지 보충합니다.

- PP 회복·스킬 성공: 손패 → 묘지. 비용·조건 실패나 취소 시 이동하지 않습니다.
- 배치 성공: 손패 → 필드. 배치 상태에 cardInstanceId를 보관하며 묘지에 넣지 않습니다.
- 퇴각·전투불능: 필드 → 묘지. 저지 관계도 해제합니다.
- 덱이 비었을 때 묘지가 있으면 전체를 덱에 되돌려 섞습니다. 필드의 카드는 회수하지 않습니다.
- 손패는 9장을 유지하도록 보충합니다. 나머지 카드가 필드에 있어 덱·묘지가 비었다면 손패가 줄거나 0장이 될 수 있습니다.
- 재순환 시 새 실물 카드를 만들지 않고 같은 instanceId를 유지합니다. 덱+손패+필드+묘지의 카드 수는 전투 내내 일정합니다.

맵의 아군을 누른 뒤 상단 퇴각 버튼으로 철수합니다. 퇴각·전투불능 모두 DP 환급은 없습니다. 돌아온 카드를 다시 뽑으면 재배치할 수 있습니다. 같은 종류를 동시에 한 기만 배치하는 규칙은 유지합니다. 죽거나 퇴각한 유닛은 다음 배치에서 최대 HP로 시작합니다.

덱이 작은 경우 묘지로 간 카드가 즉시 섞여 다시 손패에 올 수 있습니다. 손패가 비어도 강제로 카드를 생성하지 않습니다. 초기화하면 선택한 덱의 새 전투 상태를 생성해 다시 섞습니다. 로비로 나가면 해당 전투는 종료합니다.

## 코드와 검증

- deck-store.js: 보유량, 덱 검증, 저장·불러오기·선택
- screens/decks.js: 카드·덱 목록·편집·전투 덱 선택
- deck-piles.js: 섞기, 뽑기, 영역 이동과 재순환
- prototype.js: 실제 배치·스킬·퇴각·전투불능과 카드 이동 연결

`node scripts/check-decks.mjs`로 40장·종류별 3장·보유량, 저장 실패와 재로딩, 카드 수 보존과 반복 순환을 검사합니다.

이전 규칙에서 저장한 40장 미만 덱은 미완성으로 표시해 보존합니다. 미완성 상태로도 수정·저장할 수 있으며, 전투 선택은 40장으로 완성한 뒤 가능합니다. 이번 변경에서는 필드 배치 수 제한을 새로 정하지 않았습니다. 덱·묘지가 모두 비는 비정상적 또는 향후 규칙 변경 상황의 방어 처리는 유지합니다.
